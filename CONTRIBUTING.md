# Как внести вклад в Polytech Games

Привет, босс политеха! Здесь описан порядок добавления игр и исправлений. Инструкция рассчитана на участников проекта и ИИ-агентов, которые помогают им с кодом.

## Условия и пожелания

Обязательные условия для **новых игр**:

- Автор — студент группы **П-24-67Б** Высшего колледжа «Astana Polytechnic». Укажи ФИО и GitHub автора в описании PR или комментарии в начале HTML-файла.
- Игра находится в одном HTML-файле или автономной папке внутри `games/`.
- Для игры не нужны npm, сборщик, серверная часть или установка зависимостей. Она запускается из корневого `index.html` через `file://` и через GitHub Pages.
- Игровые скрипты, стили и необходимые медиа хранятся в репозитории. Никакого вредоносного кода, фишинга или майнеров.
- Есть доступное во время игры меню паузы с кнопкой **«К списку игр»**, ведущей на корневой `index.html`. Пауза останавливает игровой таймер и действия; продолжение сохраняет текущую сессию.
- Игра добавлена в каталог, README и таблицу авторов; для неё есть скриншот.

Приветствуются темы колледжа, пары, преподаватели и студенческий юмор. Другие темы тоже подходят: зомби уже в сборнике. Сенсорное управление желательно, если механика позволяет; укажи, когда нужны клавиатура и мышь.

## Карта проекта для участников и ИИ-агентов

| Что меняется | Где искать |
| --- | --- |
| Каталог, карточки и ссылки на игры | Корневой `index.html`, блок `.grid` с карточками `a.item` |
| Физрук, симулятор учителя, шутер | Соответствующий HTML-файл в `games/`: стили и JavaScript встроены |
| Механика и интерфейс новеллы Попова | `games/popov/game.js`, `index.html`, `style.css` |
| Сценарий и вопросы новеллы | `games/popov/data.js` |
| Подготовленные ресурсы новеллы | `games/popov/assets/game/` |
| Подготовка ресурсов и дизайн новеллы | `games/popov/tools/prepare_assets.py`, `games/popov/GDD.md` |
| Жан на грани | `games/zhan-na-grani/index.html` — собранный файл с минифицированным кодом; исходники и сборка у автора |
| Скриншоты и общие изображения | `screenshots/`, `assets/` |

В проекте нет общего package.json, сборки и набора автоматических тестов. Для небольших изменений достаточно целевых проверок и ручной проверки в браузере. Скрипт подготовки ресурсов новеллы — отдельный инструмент, для запуска игр он не нужен.

### Порядок работы для ИИ-агента

1. Прочитай запрос, этот файл и нужный участок кода. Проверь `git status --short`, чтобы видеть уже существующие изменения.
2. Меняй файлы, относящиеся к задаче. Сохраняй чужие незакоммиченные изменения, авторство и существующий стиль кода; не переформатируй целые файлы ради небольшой правки.
3. Сохраняй автономный запуск игр и относительные пути. Не добавляй зависимости, сборщик и внешние сервисы для задачи, которая решается текущим стеком.
4. Выполни подходящие проверки из чеклиста ниже. Не заявляй о проверке в браузере или на телефоне, если её не проводил.
5. В результате укажи, что изменено, что проверено и какие ограничения проверки остались.
6. Коммит, push и публикацию выполняй в пределах поручения пользователя; не включай в коммит посторонние изменения.

Эта инструкция не меняет авторство: ИИ помогает участнику. Не придумывай ФИО, группу, GitHub-профиль или результаты тестирования. Если данных для нового авторства нет, запроси их у участника.

## Как добавить игру

1. Положи игру в `games/<slug>/index.html` или `games/<slug>.html`. Для новых имён используй латиницу, строчные буквы и дефисы; существующие файлы переименовывать не нужно.
2. Добавь паузу, продолжение и возврат в каталог. Путь зависит от расположения точки входа:

   | Точка входа | Путь к каталогу |
   | --- | --- |
   | `games/<slug>.html` | `../index.html` |
   | `games/<slug>/index.html` | `../../index.html` |

   Используй относительные пути: `/index.html` ведёт в корень домена и не подходит для размещения сайта в `/PolytechGamesBackup/`. Если на оверлее есть обработчик продолжения по клику, останови всплытие клика на кнопке выхода.
3. Добавь PNG-скриншот в `screenshots/<slug>.png`. Выбери кадр, по которому понятна игра, без личных данных и лишнего интерфейса браузера.
4. Добавь карточку `a.item` в `.grid` корневого `index.html`. Скопируй структуру соседней карточки: ссылка, скриншот с `alt`, название, жанр, авторы и краткое описание. Проверь порядковые номера `.item-index`.
5. Обнови `README.md`: таблицу авторов и описание игры со скриншотом и управлением. Структуру проекта обновляй, если она изменилась.
6. Пройди чеклист и отправь PR.

## Как исправить существующую игру

Опиши, как воспроизвести проблему, исправь её в файлах этой игры и проверь затронутый сценарий. Если меняются клавиши, возможности или порядок запуска — обнови соответствующее описание в README. Если меняется вид карточки или основная сцена — проверь, нужен ли новый скриншот.

Для правок только документации достаточно проверить точность инструкций, Markdown и ссылки; запускать все игры не требуется.

## Чеклист проверки

Для новой игры пройди весь список. Для исправления выбери относящиеся к нему пункты и перечисли их в PR.

- [ ] Открыл корневой `index.html` локально и запустил игру через её карточку.
- [ ] Проверил загрузку изображений, стилей и скриптов: нет потерянных ресурсов и новых ошибок в консоли.
- [ ] Начал игру и проверил основные действия, завершение и перезапуск.
- [ ] Открыл паузу: игровой таймер и действия остановились; продолжение сохраняет сессию.
- [ ] Нажал «К списку игр» из паузы и попал в корневой каталог.
- [ ] Проверил пути при размещении сайта в подпапке, как на GitHub Pages.
- [ ] Если заявлена поддержка телефона — проверил сенсорное управление и размещение кнопок на узком экране. Указал, был это реальный телефон или эмуляция.
- [ ] Сверил карточку, скриншот, авторство и описание в README.
- [ ] Просмотрел diff: нет случайных файлов, секретов и посторонних изменений.

Запиши браузер и проверенные сценарии. Если что-то проверить не удалось, укажи это прямо.

Для проверки по HTTP можно запустить необязательный локальный сервер из корня проекта:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Открой `http://127.0.0.1:8000/`. Такая проверка не заменяет запуск через `file://` и проверку путей в подпапке.

## Как отправить Pull Request

1. Сделай **Fork** [репозитория](https://github.com/skippingclass/PolytechGamesBackup), если у тебя нет доступа на запись.
2. Клонируй свой форк и создай ветку:

   ```bash
   git clone https://github.com/YOUR_GITHUB_USERNAME/PolytechGamesBackup.git
   cd PolytechGamesBackup
   git switch -c feature/my-game
   ```

   Замени `YOUR_GITHUB_USERNAME` своим ником. Для исправления подойдёт ветка `fix/pause-menu`.
3. Внеси изменения и выполни проверки. Просмотри `git diff`, добавь в индекс только файлы задачи и создай коммит. Пример для новой игры в отдельной папке:

   ```bash
   git add games/my-game/ screenshots/my-game.png index.html README.md
   git commit -m "feat: add my-game"
   git push -u origin feature/my-game
   ```

4. Открой PR из своей ветки в `main` исходного репозитория. Используй шаблон ниже. Ревью проводят [@skippingclass](https://github.com/skippingclass) или [@AKDWorks](https://github.com/AKDWorks).

### Шаблон описания PR

```markdown
## Что изменилось
Кратко: новая игра или проблема и результат исправления.

## Автор новой игры

Для исправлений этот раздел можно убрать.

## Как проверить
1. Открыть корневой index.html.
2. ...

## Что проверено
- Браузер и устройство:
- Сценарии и результат:
- Что проверить не удалось:

## Скриншот
Для новой игры или изменений интерфейса.
```
